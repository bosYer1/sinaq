# Production RLS audit — 2026-08-30

Scope: GameYer production Supabase project, read-only policy inspection. No policy or production data was changed.

## Findings

- `clubs`: anonymous users can only SELECT rows accepted by `app_private.is_public_club(id)`. Authenticated non-admin users get the same public set; INSERT/UPDATE/DELETE require `is_admin()`.
- `club_pricing` and `club_opening_hours`: anonymous SELECT is limited to rows whose parent club passes `app_private.is_public_club(club_id)`; mutations require `is_admin()`.
- `club_submissions`: anonymous/authenticated INSERT is permitted only with database-owned `status='pending'` and `reviewed_at IS NULL`; SELECT/UPDATE/DELETE require `is_admin()`.
- `analytics_events`: anonymous/authenticated INSERT is constrained to public non-admin/non-api paths, bounded session/path lengths, the approved event types (`maps_click`, `phone_click`, `instagram_click`) and valid optional club slugs. Reading/deleting analytics events requires `is_admin()`.
- `admin_users`: authenticated users can only SELECT their own `user_id` row. Admin UI additionally requires MFA assurance level AAL2 before protected navigation is rendered.
- No service-role or private Supabase secret is required by the public browser client.

## Security conclusion

No accidental public write/read expansion was found in the audited tables. Existing policies are intentionally left unchanged. Any future policy migration must preserve the same least-privilege boundaries and pass the admin/submission regression gates before production merge.
